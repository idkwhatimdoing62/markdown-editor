# ADR-0004：使用预览 WebView 原生导出 PDF

> 状态：已采纳
> 日期：2026-09-04
> supersedes: ADR-0001

## 背景

`printpdf` 需要重新执行一套独立的 HTML/CSS 布局。它无法完整支持主题 CSS、浏览器字体回退、图片尺寸、Mermaid 和分页规则，因此 PDF 与预览会出现明显差异。长文档虚拟分块还可能导致只打印当前已加载的内容。

## 决策

PDF 导出以当前预览 WebView 为唯一视觉来源：

- Windows 使用 WebView2 `PrintToPdf`；
- macOS 使用 WKWebView `createPDF`；
- 导出前等待字体、图片和 Mermaid 完成；
- 虚拟长文档先挂载全部分块，再执行浏览器原生打印；
- 先写入同目录临时文件，成功后原子改名到用户选择的路径；
- `printpdf` 仅作为没有可用预览 WebView 时的兼容回退，后续验证稳定后删除。

## 原因

预览和 PDF 在同一平台上使用同一个 DOM、主题 CSS 和浏览器布局引擎，能够保持标题、字号、行距、粗体、表格、图片、背景和分页规则一致。Windows 与 macOS 仍分别使用 Chromium 和 WebKit，因此不承诺跨平台像素级一致。

## 后果

- 导出变为异步操作，界面需要显示“正在导出”状态并处理回调错误；
- 导出依赖系统 WebView 运行时；
- 长文档导出时会暂时关闭虚拟分块卸载，内存峰值可能上升；
- 平台原生 API 需要分别维护，但不再维护第二套 HTML/CSS 排版规则；
- `printpdf` 相关依赖和审计告警可以在回退移除后进一步减少。

## 验收规则

1. 当前主题、字号和深浅外观在预览与 PDF 中一致。
2. 本地图片、原始 HTML 图片、粗体、表格和 Mermaid 不因导出路径改变而丢失。
3. 10 MiB 文档导出包含所有虚拟分块，不受当前滚动位置影响。
4. 导出失败不覆盖已有 PDF，也不修改 Markdown 文档。
