# ADR-0001：HTML/PDF 采用主题一致导出

> 状态：已采纳
> 日期：2026-08-13
> 影响版本：下一发布版本起

## 背景

旧导出链路在 `export.rs` 中分别为 HTML 和 PDF 写死 CSS。用户切换主题或修改正文字号后，浏览器预览已经变化，导出文件仍使用另一套字体、颜色、间距和表格样式。预览结果无法作为导出前的可靠检查依据。

导出还要满足下面的约束：

- HTML 文件离开应用后仍能显示内置字体和本地图片；
- PDF 继续直接写入用户选择的路径；
- Windows 和 macOS 使用同一条 Rust 导出链路；
- 导出失败不能修改当前文档；
- 外部主题 CSS 的适配规则不能在导出模块中重复维护。

## 备选方案

### 方案 A：固定导出主题

为导出定义一套长期稳定的 CSS，不跟随预览主题。

优点是输出容易做跨版本快照，PDF 引擎需要支持的 CSS 范围较小。缺点是用户看到的预览无法代表导出结果，主题导入对导出无效，当前 P1 问题继续存在。

### 方案 B：主题一致导出

HTML 和 PDF 都接收当前主题 CSS、当前正文字号、文档目录和标题，使用与预览相同的 Markdown 解析选项、DOM 兼容规则和应用字体。

优点是主题、字号、加粗、代码块、表格和本地图片沿同一输入链路进入预览与导出。HTML 可以做成自包含文件。PDF 仍可直接保存到选定路径。

代价是 PDF 使用 `printpdf` 的 HTML/CSS 实现，少数浏览器专有 CSS 可能退化。PDF 不执行 JavaScript，Mermaid 围栏在 PDF 中保留为带语言标签的代码块。

### 方案 C：调用系统 WebView 打印

让 WebView 执行主题和 Mermaid，再打开系统打印窗口。

浏览器效果最接近屏幕预览。系统打印 API 在 Windows 和 macOS 上的保存流程不同，Wry 当前只提供交互式打印入口，应用无法稳定地把结果直接写入已经选定的 PDF 路径。用户还要在打印窗口再次选择输出目标。

## 决策

采用方案 B。

`export_html` 和 `export_pdf` 必须接收 `ExportOptions`。调用方负责提供活动标签的以下状态：

- 当前主题原始 CSS；
- 相对主题默认值发生变化后的正文字号覆盖；
- 当前 Markdown 文件所在目录；
- 当前文档标题。

导出模块负责：

1. 使用应用的 Markdown 兼容预处理和 `pulldown-cmark` 选项生成正文；
2. 添加与浏览器预览一致的代码语言标签、脚注 DOM 和结构兜底样式；
3. 使用 JetBrains Mono、霞鹜文楷及其粗体字重；
4. HTML 内嵌四份字体、本地图片和按需 Mermaid 运行库，输出单文件；
5. PDF 把同一主题化 DOM、字体和本地图片交给 `printpdf`，直接生成用户指定的文件；
6. 保留远程 URL，不在导出时主动联网下载资源。

一致性验收以可观察属性为准：标题颜色与边线、正文与标题字号、行距和块间距、粗体、代码块、表格、本地图片及页面背景应来自当前主题。HTML 由浏览器执行 CSS；PDF 在 `printpdf` 支持范围内执行相同 CSS。出现 PDF 专有退化时，先增加针对性兼容和回归样例；需要 JavaScript 图表或浏览器像素级输出时，重新评估方案 C。

## 结果

- 导出模块不再维护固定视觉主题；
- 新主题格式必须同时通过浏览器预览和主题化导出测试；
- HTML 文件体积会因字体、图片和 Mermaid 运行库增加；
- PDF 的浏览器专有 CSS 和 Mermaid 仍有明确能力边界；
- 后续若改用 WebView 后台打印，必须保留直接保存、跨平台行为和失败隔离三项约束。

## 验证

自动测试必须至少覆盖：

- 自定义主题 CSS 出现在完整 HTML；
- 用户字号覆盖位于主题 CSS 之后；
- HTML 包含内嵌应用字体；
- 本地相对图片转换为自包含资源；
- Mermaid 文档包含内置渲染能力；
- PDF 文件可生成且包含有效 PDF 头。
